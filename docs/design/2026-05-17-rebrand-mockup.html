§6

Bring your own data, dialog and adapter contract

file upload · YAML manifest · session-scoped

The BYOD link on the landing page promises something specific. A planner can drop their own data into a briefing without forking Riprap. The framework already supports this via the .riprap/ auto-discovery and the RIPRAP_EXTRA_MANIFESTS env var. The surface a non-engineer can use is what's missing. A dialog that accepts CSV, JSON, GeoJSON, or a YAML manifest, picks the right adapter from the file extension, lets the user assign a stone and tier, and adds the pebble to the active session.

Bring your own data

Add one or more files to this briefing without forking Riprap. Files stay in your browser. Nothing is uploaded.

1. File
↓
Drop a file here or click to choose

Supported: .csv · .json · .geojson · .yaml · .yml

2. Adapter
3. Pebble mapping

Files are parsed in the browser and held in IndexedDB for the current session. Clearing site data clears the pebble.

How the adapter chain works

  1. 1
    Detect format. File extension picks an adapter. A .csv with lat / long columns becomes socrata_records; .geojson becomes geojson_polygons; .yaml is parsed as a manifest and provides its own adapter.
  2. 2
    Sniff schema. The adapter reads the first 100 rows and proposes a field mapping. The user confirms or edits in the dialog.
  3. 3
    Write to the session registry. A pebble manifest is generated and stored in browser IndexedDB. The pebble layers onto the active deployment without re-running Riprap.
  4. 4
    Cite on the next briefing. The next briefing run includes the user's data as a card under the chosen stone. The citation reads "user · {pebble_name}" so reviewers can see what wasn't part of the public-record base.

Worked example

Riprap's examples/byod/ uses an NYC Open Data CSV with 219 FDNY firehouses as if it were a user portfolio. The same flow works for any agency CSV with an address column.

Out of scope for v0.5

  • Server-side storage. Files stay in the browser for now.
  • Cross-session sharing. A pebble lives in one user's IndexedDB.
  • Schema validation against a published JSON Schema. The adapter sniffs; it does not verify.
  • Multi-file uploads as a single pebble. One file, one pebble.
§7

Civic-tech compliance, what rulebooks this design satisfies

USWDS · GOV.UK · 508 · PWA

Civic-tech work has explicit standards. The visual system was already aligned with most of them. Federal blue, plain serif body, all-AA contrast. The brief's original copy and a few of my own decorative flourishes weren't. Below: four rulebooks the v0.5 surface satisfies, with the specific lines they cover. All four apply to any deployment that wants to ship through a US municipal IT review.

U.S. Web Design System

designsystem.digital.gov
  • ✓IBM Plex Sans, Mono, and Serif throughout. Apache 2.0 and SIL OFL licenses keep the type stack federal-procurement compatible.
  • ✓Blue-60v (#005EA2) carried as the accent and tier-empirical color, the canonical federal civic blue.
  • ✓Sentence-case headings. Hero, section heads, and chip text all sentence-case.
  • ✓No italic emphasis in headings. USWDS uses weight changes; we use bold and structure.
  • ✓Phase banner pattern follows USWDS "Site alert" on the composite hero.
  • ✓44px minimum touch targets on the address input and Brief button.
  • ✓Works with JavaScript disabled. The city rotation upgrades from a static "NYC" default; the search form is plain HTML and submits without JS.
  • ✓Skip link to main content is the first focusable element on the page.

GOV.UK Design System

design-system.service.gov.uk
  • ✓Hero is a statement of purpose, not a tagline. The H1 says what Riprap does; the deck says how.
  • ✓Bold for emphasis, not italics. The audit-trail clause in the deck uses <strong>.
  • ✓Coverage stated as fact, not aspiration. The H1 rotates through cities Riprap actually runs in.
  • ✓Phase banner mirrors GOV.UK's govuk-phase-banner with a federal-blue tag.
  • ✓Plain links use dotted underline on hover, federal blue, no decorative effects.

Section 508 + WCAG 2.2 AA

section508.gov · W3C
  • ✓All text ≥ 4.5:1 contrast. Verified per-token in tokens.css.
  • ✓3px federal-blue focus ring on all interactives with 2px offset.
  • ✓No color-only encoding. Tier glyphs carry shape; the hazard chip carries text plus a dot color.
  • ✓Reduced-motion respected. The city rotation runs without fade under prefers-reduced-motion: reduce.
  • ✓Labelled form input with <label>, aria-describedby, autocomplete="street-address", and enterkeyhint="search" for mobile keyboards.

Plain Writing Act of 2010

plainlanguage.gov · 5 USC §301
  • ✓Audience-first vocabulary. "Audit trail", "source agency", "public record". The words a planner already uses.
  • ✓Imperative voice. "Type an address. Get a written briefing."
  • ✓No internal jargon on user-facing surfaces. "Framework", ".riprap/", and "manifest" stay in the README.
  • ✓Short sentences. Hero deck is three sentences, none longer than 16 words.
  • ✓No em-dashes in user-facing copy. They read as decorative punctuation and are a common AI-writing tell. Commas, periods, and sentence splits do the same work.
  • ✓Provenance named by agency, not by data-pipeline term. "FEMA, NOAA, USGS, city open-data portals", not "primary public-record sources".

Not yet, flagging for v0.6. VPAT (Voluntary Product Accessibility Template) for federal procurement. A public a11y conformance report. First-language localisation: the framework supports it; the landing page doesn't ship strings yet. A printable methodology brief auditors can attach to a memo. None block v0.5.

§8

Transparency, about the AI and about the data

disclosure · attribution

Federal civic-tech procurement now asks two questions early. Which automated systems are in the loop, and where does the data come from. Riprap can answer both clearly. It just needs surfaces that say them out loud.

AI transparency

NIST AI RMF · algorithmic accountability
  • ✓Models named in the methodology page. Granite 4.1 8B for synthesis, Mellea for rejection sampling on the LLM path, plus a deterministic templated reconciler on the offline path.
  • ✓Both paths ship the same 13-predicate compliance audit before a briefing is returned. LLM and no-LLM tiers pass the same bar.
  • ✓Open weights. Apache 2.0 on every foundation model. No commercial APIs contacted at runtime.
  • ✓Citations are mandatory. Model outputs that can't be grounded in a source document are rejected, not paraphrased.
  • ✓Energy ledger surfaced in the print artifact: hardware target and watt-hours per briefing.

Open-data attribution

CC0 · public domain · open-data terms
  • ✓Every figure links to its source by agency name, dataset ID, and URL. Vintage shown on every evidence card.
  • ✓License-clean ingest. Source datasets are CC0, public domain, or under federal and state open-data terms. Riprap doesn't ingest data it can't redistribute.
  • ✓No endorsement implied. Riprap is independent. The Civic Hydrology palette borrows USWDS blue; the dam mark is licensed CC-BY 3.0.
  • ✓Stale data ages out visibly. A briefing pulled against a 2018 dataset shows the 2018 vintage in the cite, not a fresh-looking timestamp.
  • ✓Riprap code is Apache 2.0. No GPL contamination. No proprietary contributor agreements.

Why this matters now. The OMB M-24-10 memo and the proliferation of state-level algorithmic-accountability laws (NYC LL144, California SB 1001) all push the same direction. Civic tools using automated reasoning need to say which models are in the loop, what they were trained on, and what happens to outputs that can't be sourced. Riprap already does this work under the hood. The rebrand is partly about making it visible to the procurement reviewer, not just the engineer.

Two-tier reconciler

Every briefing routes through one of two paths. The LLM tier runs Granite 4.1 8B for synthesis with Mellea rejection sampling at draft time. The offline tier runs a deterministic templated reconciler. Both paths emit the same JSON contract and pass the same 13-predicate compliance audit before a briefing is returned. Outputs that cannot be grounded in a source document are rejected, not paraphrased.

What makes this a proper PDF, not a webpage screenshot

A PDF that ships to a planning board has to clear the same procurement bar as the web app, plus a couple more that only apply to documents.

  • ✓PDF/UA-1 tagged structure (ISO 14289-1). Every heading is a proper <H1>/<H2> tag, every paragraph a <P>, every list a <L>/<LI>. Screen readers traverse the document in reading order, not page order.
  • ✓Document metadata populated. Title, author ("Riprap framework"), subject, keywords, creator, language (en-US). Visible in any PDF viewer's Properties pane.
  • ✓Bookmarks tree for the six sections. Acrobat / Preview / Foxit users navigate by section, not by page.
  • ✓Color-independent. Tier glyphs (▮ EMP / ▢ MOD / ● PRX / ▱ SYN) carry shape, not just color. The existing print.css already degrades stones to neutral gray.
  • ✓Section 508 conformance. All claims are text, not raster. Citation numbers are real links with aria-labels, not images of brackets.
  • ✓Map graphics are vector. Address pin, flood-zone polygons, and FloodNet sensor markers ship as PDF vector objects, not embedded screenshots. Labels stay selectable; the legend swatches share the same fills as the polygons.
  • ✓Evidence cards are tagged tables. Source name, tier, figure, label, and vintage are real cells. A screen reader announces row + column instead of "image, no description".
  • ✓Running headers, page numbers, and footers on every page after the cover. A printed copy that loses page 3 is still legibly identifiable.
  • ✓Federal memo header on the cover (TO / FROM / RE / DATE). This is the format every US planning board, engineer of record, and city resilience office already files in.
  • ✓Document hash on the stamp page. Two people printing the same briefing can verify they're holding the same artifact.
  • ✓Non-affiliation repeated on the cover and the stamp. Required when a tool ingests federal/state/city data and produces a downstream artifact.
  • ✓Glossary defining every domain-specific abbreviation. A planner from outside the hydrology field can read the briefing without a parallel tab.
